Module 25 — Chatbot UI & Outbound Calls

Two FAB (Floating Action Button) components anchored to the bottom-right of the screen. The chatbot enables natural-language management of tenants and appointments. The outbound call button triggers VAPI calls to tenants or lease prospects.

Concepts Covered

  • Floating Action Button (FAB) pattern
  • useRef for scroll-to-bottom
  • ReactMarkdown for AI response rendering
  • Multi-turn conversation history
  • refresh_needed signal → window.dispatchEvent
  • Enter key submit handler
  • E.164 phone number validation regex
  • Agent selector toggle buttons
  • STATUS enum state machine
  • Framer Motion rotate animation (spinner)

Chatbot.jsx — Line-by-Line

frontend/src/components/Chatbot.jsx
const [open, setOpen] = useState(false);
const [messages, setMessages] = useState([]);
const [input, setInput] = useState('');
const [loading, setLoading] = useState(false);
const bottomRef = useRef(null);
messages is the full conversation history — all user + assistant turns. This array is sent to the backend with each request so the AI has context for follow-up questions.

Scroll-to-bottom with useRef

useEffect(() => {
    bottomRef.current?.scrollIntoView({ behavior: 'smooth' });
}, [messages, loading]);
An invisible div at the bottom of the message list: <div ref={bottomRef} />. Calling scrollIntoView() on it scrolls the chat to the latest message. Fires whenever messages or loading changes — so the "Thinking…" bubble also triggers a scroll.

Message send flow

async function handleSend() {
    const text = input.trim();
    if (!text || loading) return;

    const userMsg = { role: 'user', content: text };
    const updated = [...messages, userMsg];
    setMessages(updated);     // show user message immediately
    setInput('');
    setLoading(true);

    try {
        const data = await sendChatMessage(updated);   // send full history
        setMessages(prev => [...prev, { role: 'assistant', content: data.reply }]);
        if (data.refresh_needed) {
            window.dispatchEvent(new Event('refresh-appointments'));
        }
    } catch {
        setMessages(prev => [...prev,
            { role: 'assistant', content: 'Sorry, something went wrong. Please try again.' }
        ]);
    } finally {
        setLoading(false);
    }
}
The full conversation history is sent to the API on every turn. The backend truncates to the last 10 messages before sending to OpenAI, keeping token costs bounded. refresh_needed is a boolean in the API response. When true, it means the chatbot just mutated data (created a building, rescheduled an appointment). We dispatch an event so other components can re-fetch.

ReactMarkdown custom components

<ReactMarkdown
    components={{
        p:      ({ children }) => <p className="mb-1 last:mb-0">{children}</p>,
        strong: ({ children }) => <strong className="font-semibold">{children}</strong>,
        ul:     ({ children }) => <ul className="list-disc list-inside space-y-0.5 my-1">{children}</ul>,
        ol:     ({ children }) => <ol className="list-decimal list-inside space-y-0.5 my-1">{children}</ol>,
        code:   ({ children }) => <code className="bg-background/50 rounded px-1 text-xs font-mono">{children}</code>,
        // h1/h2/h3 mapped to p — prevents large headers in chat bubbles
        h1: ({ children }) => <p className="font-semibold mb-1">{children}</p>,
    }}
>
    {msg.content}
</ReactMarkdown>
ReactMarkdown overrides are used to apply Tailwind classes. Without custom components, React Markdown renders plain HTML that inherits the default browser styles — which look wrong in a Tailwind-styled app. Heading tags (h1-h3) are mapped to styled paragraphs. If the AI responds with a markdown header, it would be huge inside a chat bubble — so all heading levels render as bold paragraphs instead.

FAB toggle button

<motion.button
    whileHover={{ scale: 1.05 }}
    whileTap={{ scale: 0.95 }}
    onClick={() => setOpen(o => !o)}
    className="w-12 h-12 rounded-full bg-primary text-primary-foreground
                shadow-lg flex items-center justify-center"
>
    {open ? <X className="w-5 h-5" /> : <MessageCircle className="w-5 h-5" />}
</motion.button>
The FAB icon changes: MessageCircle when closed, X when open. This gives the user a clear way to dismiss the chat. The functional setState update "o => !o" is safer than "!open" — avoids stale closure issues.

OutboundCallButton.jsx — Line-by-Line

frontend/src/components/OutboundCallButton.jsx

STATUS enum

const STATUS = {
    IDLE:    'idle',
    CALLING: 'calling',
    SUCCESS: 'success',
    ERROR:   'error',
};
A string enum prevents typos like 'succcess'. The component uses a single status state variable instead of separate booleans (isCalling, isSuccess, isError). Avoids impossible states — you can't be both CALLING and ERROR simultaneously with one variable.

E.164 validation

if (!/^\+\d{7,15}$/.test(trimmed)) {
    setStatus(STATUS.ERROR);
    setErrorMsg(t('outbound.invalidNumber'));
    return;
}
E.164 format: + followed by 7–15 digits. This covers phone numbers from most countries (7-digit minimum for small island nations, 15-digit maximum per ITU-T standard). The + prefix is required — VAPI rejects numbers without it.

Agent selector

const AGENTS = [
    { id: 'complaint', label: 'Complaint Agent', description: 'Maintenance intake' },
    { id: 'lease',     label: 'Lease Agent',     description: 'Lead capture' },
];

{AGENTS.map(agent => (
    <button
        key={agent.id}
        onClick={() => {
            setAgentId(agent.id);
            if (status !== STATUS.IDLE) { setStatus(STATUS.IDLE); setErrorMsg(''); }
        }}
        disabled={isCalling}
        className={`flex-1 text-xs py-1.5 font-medium transition-colors
            ${agentId === agent.id
                ? 'bg-primary text-primary-foreground'
                : 'bg-background text-muted-foreground hover:text-foreground'

    </button>

Switching agents clears any existing error/success state so the user doesn't see a stale message from a previous call attempt. Also prevents disabled state if the previous attempt was "success" — new agent means fresh attempt.

Calling spinner animation

{isCalling ? (
    <>
        <motion.div
            animate={{ rotate: 360 }}
            transition={{ repeat: Infinity, duration: 1, ease: 'linear' }}

A CSS-only spinner (border trick: full border except transparent top edge = quarter-circle arc). Framer Motion rotate animation gives it infinite clockwise spin. repeat: Infinity means it never stops; ease: 'linear' prevents the slight speed variation that easing functions introduce.

className={`w-12 h-12 rounded-full shadow-lg flex items-center justify-center transition-colors ${

Key Patterns

Conversation history as an array of messages

The OpenAI API requires a message array in this format:

[
  { role: 'system',    content: 'You are a property manager assistant...' },
  { role: 'user',      content: 'How many vacant flats are there?' },
  { role: 'assistant', content: 'You have 3 vacant flats: A102, B201, C304.' },
  { role: 'user',      content: 'Which one is the cheapest?' },   // the new message
]

The frontend sends the full history (including the new message). The backend adds the system message before sending to OpenAI. This design means the backend can change the system prompt without any frontend changes.

refresh_needed signal

// In chatbot.py (backend):
refresh_tools = {'add_new_unit', 'add_new_building', 'reschedule_appointment', ...}
refresh_needed = last_tool_called in refresh_tools

// In POST /chat response:
{ "reply": "Done! Rescheduled for Thursday at 2pm.", "refresh_needed": true }

// In Chatbot.jsx:
if (data.refresh_needed) {
    window.dispatchEvent(new Event('refresh-appointments'));
}

The chatbot mutates data in the DB. Without a refresh signal, the calendar would show the old appointment time until the user manually refreshes. The event-based approach decouples the chatbot from the calendar — the chatbot doesn't need to know the calendar exists.

Bugs Encountered

Bug 1 — Chat window doesn't scroll to new messages
Symptom: new messages appeared below the visible area; user had to scroll manually.
Cause: useEffect ran before React rendered the new DOM node for the message.
Fix: the dependency array includes both [messages, loading] — the effect runs when loading becomes true (showing the "Thinking..." bubble) AND when messages updates (showing the response). Both trigger scrollIntoView.
Bug 2 — Sending empty message after clearing input
Symptom: pressing Enter on an empty input sent a blank message to the API.
Cause: handleSend wasn't guarding against empty text after trim().
Fix: if (!text || loading) return; at the top of handleSend.
Bug 3 — Phone number without + prefix passes regex but VAPI rejects it
Symptom: entering "14165551234" (no plus) passed front-end validation but the VAPI call returned an error.
Cause: The regex /^\+\d{7,15}$/ requires + as the first character. The bug was that the input defaulted to "+1" but users could delete the + and type a number starting with 1.
Fix: The default value "+1" is set in state. The regex validation catches numbers without + and shows an error before the API call.

Exercise 2 — Show a message count badge on the closed FAB button

When the chatbot is closed and has unread messages (messages.length > 0 and the last message is from the assistant), show a red badge with the count.

Show solution 
// Track unread count
const [unreadCount, setUnreadCount] = useState(0);

// When a new assistant message arrives and chat is closed:
useEffect(() => {
    if (!open && messages.length > 0 &&
        messages[messages.length - 1].role === 'assistant') {
        setUnreadCount(n => n + 1);
    }
}, [messages, open]);

// Clear when opened:
const handleOpen = () => { setOpen(true); setUnreadCount(0); };

// In the FAB button JSX, add relative positioning and a badge:
<div className="relative">
    <motion.button onClick={handleOpen} .../>
    {!open && unreadCount > 0 && (
        <span className="absolute -top-1 -right-1 w-5 h-5 rounded-full
                             bg-red-500 text-white text-xs flex items-center justify-center">
            {unreadCount}
        </span>
    )}
</div>

Section 1 — What You Are Building

This module covers the tenants route and schema — the innermost data layer. The highlight is computed lease fields: fields that don't exist in the database but are derived from stored dates at response time. You'll also learn the batch enrichment pattern — how the GET /tenants endpoint fetches tenant data, flat numbers, active rents, and feature flags in just 4 queries, regardless of how many tenants exist.

Three-Layer Status Rule ─────────────────────── Layer 1: Database (source of truth) tenants.lease_start_date = "2025-01-01" tenants.lease_end_date = "2025-12-31" tenants.rent_status = "On-time" ← stored, manager manually updates Layer 2: API computed field (derived at response time) TenantResponse.lease_status = "Active" | "Expiring Soon" | "Expired" | "No Lease" TenantResponse.remaining_time_on_lease_days = 213 (these are NOT stored in DB — calculated by Pydantic @computed_field) Layer 3: Frontend display badge color = green / yellow / red (driven by lease_status string) countdown = "213 days remaining" (driven by remaining_time_on_lease_days) Rule: Never store a value that can be computed from other stored values. The computed layer ensures the frontend always has fresh, consistent data.

Section 2 — Concept Deep-Dives

Pydantic V2 @computed_field and @property

In Pydantic V2, @computed_field marks a Python @property as a field that should be included in serialized output (JSON responses). Without it, properties are excluded from .model_dump() and API responses.

pythonfrom pydantic import BaseModel, computed_field
from datetime import date

class TenantResponse(BaseModel):
    lease_start_date: Optional[date] = None
    lease_end_date:   Optional[date] = None

    @computed_field
    @property
    def lease_status(self) -> str:
        if not self.lease_start_date or not self.lease_end_date:
            return "No Lease"
        today = date.today()
        if self.lease_end_date < today:
            return "Expired"
        remaining = (self.lease_end_date - today).days
        if remaining <= 30:
            return "Expiring Soon"
        if self.lease_start_date <= today:
            return "Active"
        return "Upcoming"

# When serialized to JSON, lease_status appears as a top-level field
t = TenantResponse(lease_start_date=date(2025,1,1), lease_end_date=date(2025,12,31))
t.model_dump()
# → {"lease_start_date": "2025-01-01", "lease_end_date": "2025-12-31",
#    "lease_status": "Active", ...}

Pydantic V2 change: In Pydantic V1, you would use @validator or @root_validator for this. In V2, always use @computed_field + @property. The V1 @validator decorator is removed in V2.

Batch Enrichment Pattern — avoiding N+1 across multiple tables

The GET /tenants endpoint returns tenants enriched with data from 3 other tables (flats, rents, feature flags). With N+1, it would be 1 + (3 × N) queries. With batch enrichment, it's always exactly 4 queries no matter how many tenants.

python# Step 1: Fetch all tenants
tenants = db.table("tenants").select("*").execute().data

# Step 2: Collect all flat_uuids from those tenants
flat_uuids = [t["flat_uuid"] for t in tenants if t.get("flat_uuid")]

if flat_uuids:
    # Step 3a: Fetch flat numbers + integer IDs (for feature lookup) in ONE query
    flats_resp = db.table("flats").select("uuid, id, flat_number").in_("uuid", flat_uuids).execute()
    flat_map = {f["uuid"]: f for f in flats_resp.data}  # keyed for O(1) lookup
    flat_id_by_uuid = {f["uuid"]: f["id"] for f in flats_resp.data}

    # Step 3b: Fetch active rents for those flats in ONE query
    rents_resp = (
        db.table("rents")
        .select("flat_uuid, monthly_rent, effective_from")
        .in_("flat_uuid", flat_uuids)
        .eq("is_active", True)
        .execute()
    )
    rent_map = {r["flat_uuid"]: r for r in rents_resp.data}

    # Step 3c: Fetch feature flags for all those flats in ONE query
    flat_ids = list(flat_id_by_uuid.values())
    feature_resp = (
        db.table("property_features")
        .select("unit_id, feature_key, enabled")
        .in_("feature_key", ["tenant_details", "tenant_documents"])
        .in_("unit_id", flat_ids)
        .execute()
    )
    tenant_details_map = {}
    tenant_documents_map = {}
    for row in feature_resp.data:
        if row["feature_key"] == "tenant_details":
            tenant_details_map[row["unit_id"]] = row["enabled"]
        elif row["feature_key"] == "tenant_documents":
            tenant_documents_map[row["unit_id"]] = row["enabled"]

# Step 4: Enrich each tenant dict in Python (O(1) per tenant using maps)
for t in tenants:
    fid = t.get("flat_uuid")
    flat = flat_map.get(fid) if fid else None
    rent = rent_map.get(fid) if fid else None
    unit_int_id = flat_id_by_uuid.get(fid) if fid else None

    t["flat_number"] = flat["flat_number"] if flat else None
    t["rent_amount"] = rent["monthly_rent"] if rent else None
    t["due_date"]    = rent["effective_from"] if rent else None
    # Feature flag defaults: tenant_details=True, tenant_documents=False
    t["tenant_details_enabled"]   = tenant_details_map.get(unit_int_id, True)  if unit_int_id else True
    t["tenant_documents_enabled"] = tenant_documents_map.get(unit_int_id, False) if unit_int_id else False

The feature flag lookup uses the flat's integer id (flat.id), not the UUID. The property_features table's unit_id column is an integer FK. This is a legacy inconsistency in the schema — the flat table has both an integer PK and a UUID PK, and feature flags happened to use the integer one.

IST Timezone — Why Store Local Time?

Best practice is to store all timestamps in UTC and convert to local time on display. This codebase stores timestamps in IST (India Standard Time = UTC+5:30) for a single-region product. The timezone is applied at write time:

pythonfrom datetime import datetime, timezone, timedelta

IST = timezone(timedelta(hours=5, minutes=30))

# Get current time in IST
now_ist = datetime.now(IST)

# Format for DB storage / API response (T separator for parseISO compatibility)
formatted = now_ist.strftime("%Y-%m-%dT%H:%M:%S")
# → "2025-06-01T14:30:00"

Known trade-off: If the product ever expands beyond India, all timestamps stored as IST would need migration to UTC. This is a deliberate shortcut for the MVP scope.

Server-Side vs Client-Side Filtering for lease_status

lease_status is a computed field — it does not exist in the database. When the frontend wants to filter tenants by lease_status, the database cannot do it with a WHERE clause. The API must filter in Python after fetching all rows.

pythondef _compute_lease_status(tenant: dict) -> str:
    """Compute lease status from raw tenant dict for server-side filtering."""
    start = tenant.get("lease_start_date")
    end = tenant.get("lease_end_date")
    if not start or not end:
        return "No Lease"
    today = date.today()
    end_date = date.fromisoformat(end) if isinstance(end, str) else end
    ...

# Used in GET /tenants when lease_status filter is provided
if lease_status:
    tenants = [t for t in tenants if _compute_lease_status(t) == lease_status]

Notice this is a standalone function (_compute_lease_status) that operates on a raw dict, not a Pydantic model. That's because at this point in the route handler the tenants are still plain Python dicts from the DB response. The Pydantic @computed_field version on TenantResponse does the same logic but runs after the model is instantiated.

TenantResponse — all four computed fields

pythonclass TenantResponse(TenantBase):
    # ─── Stored fields ────────────────────────────────────────
    id: int
    uuid: UUID
    flat_uuid: Optional[UUID] = None
    created_at: datetime
    lease_start_date: Optional[date] = None
    lease_end_date: Optional[date] = None
    rent_status: Optional[str] = None
    payment_schedule: Optional[str] = None
    manager_notes: Optional[str] = None
    document_urls: Optional[list[str]] = []

    # ─── Joined from other tables (set by route handler before validation) ──
    flat_number: Optional[str] = None          # from flats table
    rent_amount: Optional[float] = None        # from rents table (active rent)
    due_date: Optional[date] = None            # from rents.effective_from
    tenant_details_enabled: Optional[bool] = None   # from property_features
    tenant_documents_enabled: Optional[bool] = None # from property_features

    model_config = ConfigDict(from_attributes=True)

    # ─── Computed fields (derived at serialization time) ─────

    @computed_field
    @property
    def tenancy_duration_months(self) -> Optional[int]:
        """Months since the tenant record was created."""
        if not self.created_at:
            return None
        now = datetime.now(tz=self.created_at.tzinfo)
        return max(0, int((now - self.created_at).days / 30))

    @computed_field
    @property
    def lease_duration_months(self) -> Optional[int]:
        """Total months covered by the lease contract."""
        if not self.lease_start_date or not self.lease_end_date:
            return None
        return max(0, int((self.lease_end_date - self.lease_start_date).days / 30))

    @computed_field
    @property
    def remaining_time_on_lease_days(self) -> Optional[int]:
        """Days remaining until lease_end_date (negative if expired)."""
        if not self.lease_end_date:
            return None
        return (self.lease_end_date - date.today()).days

    @computed_field
    @property
    def lease_status(self) -> str:
        """Derived status: Active | Expiring Soon | Expired | No Lease."""
        if not self.lease_start_date or not self.lease_end_date:
            return "No Lease"
        today = date.today()
        if self.lease_end_date < today:
            return "Expired"
        remaining = (self.lease_end_date - today).days
        if remaining <= 30:
            return "Expiring Soon"
        if self.lease_start_date <= today:
            return "Active"
        return "Upcoming"

Key subtleties:

  • tenancy_duration_months uses datetime.now(tz=self.created_at.tzinfo) — it matches the timezone of the stored created_at to avoid timezone arithmetic errors
  • Both duration fields use max(0, ...) — prevents negative values if dates are accidentally inverted
  • remaining_time_on_lease_days can be negative (lease expired) — the frontend uses this for showing "X days overdue"
  • lease_status checks Expired → Expiring Soon → Active in that order — the checks are mutually exclusive but must be evaluated in this priority

Section 4 — tenants.py Route Walkthrough

VAPI endpoints at the top — GET /tenants/by-flat/{flat_no}

Like flats.py, tenant VAPI endpoints are registered before dynamic /{tenant_uuid} routes to avoid route shadowing:

python@router.get("/by-flat/{flat_no}")
async def get_tenant_by_flat(flat_no: str, ...):
    try:
        normalized_flat_no = flat_no.strip()

        flat_response = (
            db.table("flats")
            .select("uuid, flat_number, tenant_uuid")
            .ilike("flat_number", normalized_flat_no)
            .execute()
        )
        if not flat_response.data:
            return JSONResponse(status_code=200, content={"exists": False})

        flat = flat_response.data[0]
        flat_uuid = flat['uuid']

        # Bidirectional lookup: try both FK directions
        tenant_response = db.table("tenants").select("name, phone").eq("flat_uuid", flat_uuid).execute()
        if (not tenant_response.data) and flat.get("tenant_uuid"):
            tenant_response = db.table("tenants").select("name, phone").eq("uuid", flat["tenant_uuid"]).execute()

        current_time_str = datetime.now(IST).strftime("%Y-%m-%dT%H:%M:%S")

        if not tenant_response.data:
            # Flat exists but vacant — exists=True, tenant_name=None
            return JSONResponse(status_code=200, content={
                "exists": True,
                "flat_no": str(flat['flat_number']),
                "tenant_name": None,
                "tenant_phone": None,
                "datetime": current_time_str,
            })

        tenant = tenant_response.data[0]
        return JSONResponse(status_code=200, content={
            "exists": True,
            "flat_no": str(flat['flat_number']),
            "tenant_name": str(tenant['name']),
            "tenant_phone": str(tenant['phone']),
            "datetime": current_time_str,
        }, headers={"Content-Type": "application/json"})

    except Exception as e:
        print(f"Error in tenant lookup for flat {flat_no}: {str(e)}")
        return JSONResponse(status_code=200, content={"exists": False})

JSONResponse with an explicit Content-Type header is used instead of returning a plain dict. This is because some VAPI SDK versions were observed to not parse the response correctly without the explicit header. Using JSONResponse gives explicit control over headers.

GET /tenants — full handler with all filters

python@router.get("", response_model=List[TenantResponse])
async def get_all_tenants(
    property_id: Optional[int] = Query(None),
    building_id: Optional[int] = Query(None),
    unit_uuid: Optional[str] = Query(None),
    lease_status: Optional[str] = Query(None),   # "Active" | "Expiring Soon" | "Expired" | "No Lease"
    rent_status: Optional[str] = Query(None),    # stored field — DB can filter
    unassigned: Optional[bool] = Query(None),    # true = tenants with no flat
    sort_by: Optional[str] = Query(None),
    sort_order: str = Query("asc"),
    user=Depends(require_active_subscription), db=Depends(get_authenticated_db),
):
    response = db.table("tenants").select("*").execute()
    tenants = response.data or []

    # Python-side filters (cannot be pushed to DB for computed fields)
    if unassigned:
        tenants = [t for t in tenants if not t.get("flat_uuid")]
    if unit_uuid:
        tenants = [t for t in tenants if t.get("flat_uuid") == unit_uuid]
    if rent_status:  # stored field — filter before enrichment
        tenants = [t for t in tenants if t.get("rent_status") == rent_status]
    if lease_status:  # computed field — filter after dates are available
        tenants = [t for t in tenants if _compute_lease_status(t) == lease_status]

    # ... (batch enrichment adds flat_number, rent_amount, due_date, feature flags) ...

    # Sorting
    if sort_by == "lease_end_date":
        tenants.sort(
            key=lambda t: t.get("lease_end_date") or "9999-12-31",
            reverse=(sort_order == "desc")
        )
    else:
        tenants.sort(key=lambda t: t.get("created_at") or "", reverse=True)

    return tenants

The sorting trick: t.get("lease_end_date") or "9999-12-31" puts tenants with no lease end date at the end of ascending order (9999 is far in the future). This is a simple sentinel value that avoids a None comparison error.

POST /tenants — bidirectional link on create

python@router.post("", response_model=TenantResponse, status_code=201)
async def create_tenant(tenant_data: TenantCreate, ...):
    tenant_dict = tenant_data.model_dump(mode='json')  # serializes UUID and date to str

    if tenant_data.flat_uuid:
        flat = db.table("flats").select("uuid").eq("uuid", str(tenant_data.flat_uuid)).execute()
        if not flat.data:
            raise HTTPException(status_code=404, detail="Flat not found")

    response = db.table("tenants").insert(tenant_dict).execute()
    new_tenant = response.data[0]

    # Bidirectional link: update flat to point back at new tenant
    if tenant_data.flat_uuid:
        db.table("flats").update({
            "tenant_uuid": new_tenant["uuid"],
            "occupied": True,
        }).eq("uuid", str(tenant_data.flat_uuid)).execute()

    return new_tenant

model_dump(mode='json') is the Pydantic V2 way to get a serializable dict where all types (UUID, date, datetime) are already converted to JSON-compatible strings. This avoids the manual str(v) if isinstance(v, UUID) pattern used in older code.

DELETE /tenants/{tenant_uuid} — cascade to flat and rent

python@router.delete("/{tenant_uuid}", status_code=204)
async def delete_tenant(tenant_uuid: str, ...):
    # Find the flat this tenant occupies (if any)
    flat_resp = db.table("flats").select("uuid").eq("tenant_uuid", tenant_uuid).execute()
    if flat_resp.data:
        flat_uuid = flat_resp.data[0]["uuid"]
        db.table("rents").delete().eq("flat_uuid", flat_uuid).execute()
        db.table("flats").update({
            "tenant_uuid": None, "occupied": False
        }).eq("uuid", flat_uuid).execute()

    db.table("tenants").delete().eq("uuid", tenant_uuid).execute()
    return None

Deleting a tenant must: (1) remove their rent record, (2) vacate their flat (clearing both tenant_uuid and occupied), and (3) delete the tenant. Not doing step 2 would leave the flat showing as occupied with a null tenant — a ghost occupancy.

Section 5 — Real Bugs We Hit

Bug: remaining_time_on_lease_days was always None for tenants without a lease

Symptom: Frontend showed "undefined days" instead of "No Lease" for tenants with no dates set.

Root cause: The frontend was checking remaining_time_on_lease_days !== null to decide whether to show the countdown, but remaining_time_on_lease_days is None when there's no lease_end_date. The fix was reading lease_status === "No Lease" instead — a more explicit check.

Lesson: Always use the string status field for display logic. Never try to infer status from a numeric field being null.

Bug: Batch enrichment skipped when no tenants had a flat

Symptom: After filtering tenants with unassigned=true, calling the enrichment code raised a NameError on flat_map (variable not defined). Only happened when no tenants had a flat assigned.

Root cause: The if flat_uuids: block defined flat_map, rent_map, etc. — but the else: branch only defined flat_map = {} and forgot the other maps. The tenant enrichment loop then referenced flat_id_by_uuid which didn't exist.

Fix:

pythonelse:
    flat_map = {}
    flat_id_by_uuid = {}    # was missing
    rent_map = {}
    tenant_details_map = {} # was missing
    tenant_documents_map = {} # was missing
Bug: model_dump(mode='json') vs model_dump(exclude_unset=True) confusion

Symptom: PATCH /tenants/{uuid} was overwriting existing document_urls with null when the caller didn't include that field.

Root cause: Using model_dump(mode='json') on a PATCH schema includes all fields with their defaults, including None-defaulted ones the caller never sent.

Fix: PATCH operations should always use exclude_unset=True to only include fields the caller explicitly provided:

python# CREATE: use mode='json' (want all fields, serialize types)
tenant_dict = tenant_data.model_dump(mode='json')

# UPDATE: use exclude_unset=True (only fields the caller sent)
update_data = tenant_data.model_dump(exclude_unset=True, mode='json')

Exercise 3 Hard

Add a new endpoint GET /tenants/expiring-leases that returns all tenants whose lease expires within the next N days, where N is a required query parameter. The endpoint should accept days: int and return tenants sorted by lease_end_date ascending (soonest expiry first). Include the full enriched TenantResponse for each tenant.

Full worked solution 
pythonfrom datetime import date, timedelta

@router.get("/expiring-leases", response_model=List[TenantResponse])
async def get_expiring_leases(
    days: int = Query(..., ge=1, le=365, description="Days until lease expiry"),
    user=Depends(require_active_subscription),
    db=Depends(get_authenticated_db),
):
    today = date.today()
    cutoff = today + timedelta(days=days)

    # DB-level filter: lease_end_date is stored, so we can filter directly
    response = (
        db.table("tenants")
        .select("*")
        .gte("lease_end_date", str(today))          # not yet expired
        .lte("lease_end_date", str(cutoff))          # expires within N days
        .order("lease_end_date", desc=False)
        .execute()
    )
    tenants = response.data or []

    # Batch enrichment (same pattern as GET /tenants)
    flat_uuids = [t["flat_uuid"] for t in tenants if t.get("flat_uuid")]
    if flat_uuids:
        flats_resp = db.table("flats").select("uuid, id, flat_number").in_("uuid", flat_uuids).execute()
        flat_map = {f["uuid"]: f for f in flats_resp.data}
        rents_resp = (
            db.table("rents").select("flat_uuid, monthly_rent, effective_from")
            .in_("flat_uuid", flat_uuids).eq("is_active", True).execute()
        )
        rent_map = {r["flat_uuid"]: r for r in rents_resp.data}
    else:
        flat_map = {}
        rent_map = {}

    for t in tenants:
        fid = t.get("flat_uuid")
        flat = flat_map.get(fid) if fid else None
        rent = rent_map.get(fid) if fid else None
        t["flat_number"] = flat["flat_number"] if flat else None
        t["rent_amount"] = rent["monthly_rent"] if rent else None
        t["due_date"] = rent["effective_from"] if rent else None
        t["tenant_details_enabled"] = True
        t["tenant_documents_enabled"] = False

    return tenants

Note: this new endpoint must be registered before /{tenant_uuid} in the file, otherwise FastAPI would match the path /expiring-leases as tenant_uuid="expiring-leases".

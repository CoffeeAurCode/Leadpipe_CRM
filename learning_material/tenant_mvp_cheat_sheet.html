2 · Data Hierarchy & Key FKs

PropertyGroup (properties_list)
  └── Building (buildings)
        └── Flat (flats)  ←→  Tenant (tenants)   [bidirectional FK]
              └── Complaint (complaints)
                    └── Appointment (appointments)
              └── Rent (rents)
        └── LeaseListing (lease_listings) → LeadPipeline (lease_leads)
  • flats.tenant_uuid ↔ tenants.flat_uuid — bidirectional, must stay in sync (only via assign/unassign endpoints)
  • complaints.flat_uuid → flats · appointments.complaint_uuid → complaints · rents.flat_uuid → flats
  • manager_vapi_config.manager_id → auth.users (one per manager) · twilio_number_pool.assigned_manager_id → auth.users (nullable, UNIQUE)
  • tenants.preferred_language — write-once language memory (migration 032, drives call routing)

3 · Non-Negotiable Rules

Rule 1 · No /api prefix on ANY route
Rule 2 · All frontend HTTP through apiService.js — never inline fetch
Rule 3 · Never use SQLAlchemy models — Supabase SDK directly
Rule 4 · User routes → get_authenticated_db · webhooks/admin → get_service_db
Rule 5 · VAPI endpoints always return HTTP 200 — never raise
Rule 6 · Pydantic V2 — model_validator / field_validator (never @validator)
Rule 7 · Groq model: llama-3.3-70b-versatile (3.1 is decommissioned)
Rule 8 · Dates: YYYY-MM-DDTHH:MM:SS (T separator) for parseISO
Rule 9 · Datetimes stored as IST (+05:30, no offset suffix)
Rule 10 · flats INSERT uses service-role client (RLS INSERT policy)
Rule 11 · A matching gate must never be stricter than its ranker — one scoring path
Rule 12 · Anything spoken on a call is per-language config or derived under the language lock — never a shared static string
Rule 13 · Flat number is a label, not a key — every flat lookup is building/manager-scoped; UUIDs are the identity

7 · VAPI Patterns

# Always 200 — errors are data the agent can speak
@router.post("/flats/verify-phone")
async def verify_phone(payload: PhonePayload):
    try:
        return {"status": "valid", "flat_number": flat_number}
    except Exception as e:
        return {"status": "error", "message": str(e)}   # still 200

# Empty-string params: VAPI sends "" for unconfirmed int/float fields
bedrooms: Optional[str] = None      # NOT int — parse with _parse_int()

# serverMessages for lease agents: ["end-of-call-report"] ONLY
# adding "tool-calls" silently breaks all tool calling
  • Normalize all speech-derived inputs: .strip().upper() flat numbers, tolerant size/number parsing.
  • Deterministic over model-dependent: request-start fillers (not "remember to say…"), static firstMessage after handoff, URL-tagged language capture, backend-stamped Montréal clock, three redundant lead-capture layers.
  • City matching: normalize → exact → phonetic → fuzzy → score → band (accept / confirm / reject). Corpus tests in tests/test_city_matching.py.

11 · Frontend Patterns

// apiService.js — the only place fetch lives
const authFetch = async (path, options = {}) => {
  const token = await getToken();
  const res = await fetch(`${BASE_URL}${path}`, { ...options,
    headers: { 'Content-Type': 'application/json',
               Authorization: `Bearer ${token}`, ...options.headers } });
  if (res.status === 401) { signOut(); return; }        // who are you?
  if (res.status === 403) { redirect('/pricing'); return; } // paywall ≠ logout
  return res.json();
};

// Cross-component refresh after mutations (chatbot, voice, CRUD):
window.dispatchEvent(new Event('refresh-appointments'));
useEffect(() => { const h = () => fetchData();
  window.addEventListener('refresh-appointments', h);
  return () => window.removeEventListener('refresh-appointments', h); }, []);

12 · AI Facts

  • Chatbot: gpt-4o-mini · run_chat(messages, db) → (reply, refresh_needed) · last 10 messages · {today} injected into system prompt · tool results are strings · refresh_needed=True on any write tool · hallucinated-tool guard: catch BadRequestError with "tool_use_failed", retry without tools.
  • Extraction: Groq llama-3.3-70b-versatile · extract_complaint_from_transcript() → {flat_number, category, priority, description} · category must be in ALLOWED_CATEGORIES (water, electricity, cleaning, noise, maintenance, security, other) · missing fields → null, never guessed · rule-based extractor runs first, AI is fallback.

13 · Stripe Flow

403 → /pricing → POST /payments/create-checkout-session
→ Stripe Checkout (14-day trial + $1 verify) → webhook events
→ dedupe via stripe_events (event_id UNIQUE) → subscriptions table
→ frontend polls GET /payments/subscription-status

states: trialing → active → past_due → cancelled → expired

14 · VAPI Provisioning Flow

First property group created → BackgroundTask provision_vapi_for_manager:
1. exit if manager_vapi_config already active
2. race guard: UNIQUE INDEX on twilio_number_pool(assigned_manager_id)
3. claim oldest available pool number → 'assigned'
4. create assistant via build_lease_config(backend_url, manager_id)
5. link number: httpx.patch direct (SDK phone_numbers.update is broken)
6. upsert manager_vapi_config status='active' | on failure 'failed'
Subsequent groups: skipped — one number per manager

15 · Feature Flags (per building, property_features)

Default enabled: rent_management, rent_due_date, flat_details, voice_calls, tenant_details. Default disabled: sms_reminders, email_reminders, tenant_documents. Check via Depends(require_feature(Feature.X, building_id)).

19 · Deploy & Ops Discipline (Modules 27–29)

  • Three surfaces: backend (git push → Render), agent config (backend/scripts/*.py → VAPI), schema (numbered SQL in Supabase). Name the surface before deciding how to ship.
  • Agent config: always --dry-run → read the diff → push → read back live state (vapi_inspect.py).
  • Risky shared-config change: write the rollback snapshot (live values + idempotent restore) before the change.
  • Multi-system feature order: ① DB migration → ② tolerant backend → ③ agents/provisioning → ④ flip routing. Never reorder.
  • Migrations: numbered, small, idempotent (IF NOT EXISTS), CHECK-constrained; constraint-adding = clean data → stop producing dirt → lock (three steps).
  • RLS evolution: fix coverage gaps with additive policies; inspect with SELECT * FROM pg_policies WHERE tablename='…'; never "temporarily" bypass with service-role.
  • Tests at the failing layer: query bug → contract test on the SELECT; matcher bug → corpus test; conversation bug → repeated live calls (non-determinism!); route bug → integration test.
  • Test ladder: pytest backend/tests/unit → backend/tests/integration → tests/test_city_matching.py → Playwright e2e/ → smoke_test_leasing.ps1 against prod.
  • ImportError in tests? Stale venv before code: pip install -r requirements.txt.
  • Triage rule: classify every production observation as defect / artifact / needs-evidence — only defects get fixes.

Section 1 — What You Are Building

main.py is the application's single entry point — the file that Uvicorn imports to get the FastAPI app object. It does three things: creates the FastAPI app, configures CORS (which origins can call the API), and mounts all 18 route modules. config.py is the application's configuration hub — it reads every environment variable once at import time and exposes them as a typed singleton.

┌─ main.py ──────────────────────────────────────────┐ │ │ uvicorn ────────►│ app = FastAPI() │ (server) │ app.add_middleware(CORSMiddleware, ...) │ │ app.include_router(complaints.router) │ │ app.include_router(voice.router) │ │ app.include_router(...) × 18 routers │ │ │ │ @app.get("/") → health check │ └───────────┬──────────────────────────────────────────┘ │ imports ┌─ config.py ─┐ │ Settings │◄─── .env file (via python-dotenv) │ singleton │ └─────────────┘

Section 2 — Concept Deep-Dives

FastAPI — How it works

FastAPI is an ASGI web framework. You create an app object, attach routes to it using decorators, and Uvicorn (the ASGI server) receives HTTP requests and calls the appropriate route handler. FastAPI reads your Python type hints to auto-generate request validation, response serialization, and OpenAPI docs.

Minimal standalone example

from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")
async def hello():
    return {"message": "world"}

# Run with: uvicorn main:app --reload
# Visit http://localhost:8000/hello → {"message": "world"}
# Visit http://localhost:8000/docs  → Swagger UI auto-generated

How this project uses it

The app is created in main.py with app = FastAPI(title="AI Complaint System"). The title appears in the Swagger docs. Routes are never defined directly in main.py — they live in separate router files and get mounted via include_router().

What breaks without it

If you removed FastAPI and used raw Python sockets, you'd need to manually parse HTTP headers, validate request bodies, serialize responses to JSON, handle async, and write your own OpenAPI spec. FastAPI automates all of this.

Try it yourself

Create a file hello.py, paste the example above, and run uvicorn hello:app --reload. Then visit http://localhost:8000/docs.

Success: you see Swagger UI with one endpoint: GET /hello. Clicking "Try it out" → "Execute" returns {"message": "world"}.

APIRouter — Splitting routes across files

An APIRouter is a mini-app that holds a group of related routes. You create one per feature area (complaints, tenants, flats, etc.), attach routes to it with decorators, and then mount it into the main app via app.include_router(). This is the FastAPI equivalent of Express.js's router or Django's URL config.

Minimal standalone example

# complaints.py
from fastapi import APIRouter

router = APIRouter(prefix="/complaints", tags=["Complaints"])

@router.get("")          # ← full path becomes GET /complaints
async def list_complaints():
    return ["complaint 1", "complaint 2"]

@router.post("")         # ← POST /complaints
async def create_complaint():
    return {"created": True}

# main.py
from fastapi import FastAPI
from complaints import router as complaints_router

app = FastAPI()
app.include_router(complaints_router)
# Now GET /complaints and POST /complaints both work

What breaks without it

Without APIRouter, all 80+ route handlers would live in main.py, making it thousands of lines long and impossible to navigate. The prefix parameter prevents repeating /complaints in every route path.

This project has no /api prefix. Routes are registered as /complaints, not /api/complaints. The frontend sends requests to /complaints directly. Never add an /api prefix — it would break all existing VAPI and Stripe webhook integrations.

CORS — Cross-Origin Resource Sharing

Browsers block JavaScript from calling APIs on a different origin (domain + port) than the page itself. This is the Same-Origin Policy. CORS is the mechanism that allows a server to explicitly say "I accept requests from this other origin." Without CORS headers, the browser would block all API calls from the React frontend (port 5173) to the FastAPI backend (port 8000).

Minimal standalone example

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # only this origin
    allow_credentials=True,                   # allow cookies + auth headers
    allow_methods=["*"],                       # GET, POST, PATCH, DELETE, etc.
    allow_headers=["*"],                       # Authorization, Content-Type, etc.
)

How this project uses it

Allowed origins are read from the ALLOWED_ORIGINS env var (comma-separated). This means dev (localhost:5173) and production (your deployed frontend URL) are both valid without a code change — just update the env var.

Why allow_credentials=True matters

This allows the browser to send cookies and the Authorization header in cross-origin requests. Without it, the JWT token in the Authorization: Bearer ... header would be stripped by the browser before reaching the server.

CORS does NOT apply to server-to-server calls. Stripe webhooks and VAPI webhooks are sent server-to-server (Stripe's servers → your server), not from a browser. They bypass CORS entirely. You still validate them using signature verification instead.

Settings Singleton — config.py

A singleton is an object created once, globally, and reused everywhere. config.py creates one Settings instance and exports it as settings. Any file that imports from app.config import settings gets the exact same object — there's no re-reading of .env on every import.

Why a class instead of module-level variables?

Grouping settings in a class makes them easier to pass around, mock in tests, and discover via IDE autocomplete. Compare:

# Without class (module-level)
SUPABASE_URL = os.getenv("SUPABASE_URL", "")    # can't import just the config object

# With class (this project)
class Settings:
    SUPABASE_URL: str = os.getenv("SUPABASE_URL", "")

settings = Settings()  # one instance, imported everywhere

The default value pattern

Every os.getenv() call has a second argument — the default if the variable is missing. Most defaults are empty strings "". This means the server starts even with missing vars (it fails later, when the missing config is actually used), rather than crashing immediately at import time.

Section 3 — Line-by-Line Walkthrough

File: backend/app/config.py

Read this file first — main.py imports from it, so it runs before main.py's body executes.

from dotenv import load_dotenv   # reads .env file
import os

load_dotenv()   # must run before any os.getenv() call
load_dotenv() — reads the .env file in the current working directory (or any parent directory) and injects its key=value pairs into the process's environment. After this line, os.getenv("SUPABASE_URL") returns the value from .env. This must run before the Settings class body, because Python evaluates class-level assignments immediately. 
class Settings:
    SUPABASE_URL: str = os.getenv("SUPABASE_URL", "")
    SUPABASE_KEY: str = os.getenv("SUPABASE_KEY", "")
    SUPABASE_SERVICE_KEY: str = os.getenv("SUPABASE_SERVICE_KEY", "")
    SUPABASE_JWT_SECRET: str = os.getenv("SUPABASE_JWT_SECRET", "")
Class-level attributes with type annotations — Python evaluates these when the class is defined (at import time, not at instantiation). The : str annotation is a hint only — Python does not enforce it at runtime. The value is set by os.getenv(), which returns the env var's value or the default (""). 
    OPEN_AI_API: str = os.getenv("OPEN_AI_API", "")
    PRIVATE_VAPI_API: str = os.getenv("PRIVATE_VAPI_API", "")
    VAPI_COMPLAINT_ASSISTANT_ID: str = os.getenv("VAPI_COMPLAINT_ASSISTANT_ID", "")
    VAPI_COMPLAINT_NUMBER_ID: str = os.getenv("VAPI_COMPLAINT_NUMBER_ID", "")
    BACKEND_URL: str = os.getenv("BACKEND_URL", "https://tenant-management-mvp.onrender.com")
    DEBUG: bool = os.getenv("DEBUG", "False").lower() == "true"
    ALLOWED_ORIGINS: str = os.getenv("ALLOWED_ORIGINS", "")
Boolean parsing: environment variables are always strings. os.getenv("DEBUG", "False") returns the string "False". Comparing it to "true" (lowercase) after calling .lower() converts it to the Python bool False. This is the standard pattern for boolean env vars.

BACKEND_URL has a non-empty default — this is intentional. The VAPI agent config uses this URL to build tool call URLs. If the env var is missing, the production URL is used as a fallback so scripts don't accidentally target localhost. 
    STRIPE_SECRET_KEY: str = os.getenv("STRIPE_SECRET_KEY", "")
    STRIPE_WEBHOOK_SECRET: str = os.getenv("STRIPE_WEBHOOK_SECRET", "")
    STRIPE_PRICE_ID: str = os.getenv("STRIPE_PRICE_ID", "")
    FRONTEND_URL: str = os.getenv("FRONTEND_URL", "http://localhost:5173")
    LANDING_PAGE_URL: str = os.getenv("LANDING_PAGE_URL", "http://localhost:3000")

settings = Settings()   # the singleton — imported everywhere as "from app.config import settings"
settings = Settings() — creates exactly one Settings instance. Python's module system caches imports, so every file that writes from app.config import settings receives this exact same object. There is no second instance created anywhere.

File: backend/app/main.py

from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from app.routes import (
    complaints, voice, call_logs, flats, appointments, tenants,
    properties, settings, rents, buildings, property_types,
    property_groups, upload, workflow, chat, payments, notifications,
    import_routes, leasing,
)
from app.config import settings as config
Import aliasing: from app.config import settings as config — there's a naming collision: the routes/settings.py module is imported as settings, and the config singleton is also called settings. The alias config resolves the ambiguity. This is the only place this alias appears; all other files import from app.config directly without aliasing. 
app = FastAPI(title="AI Complaint System")
FastAPI(title=...) — creates the ASGI application. The title appears in the auto-generated OpenAPI JSON at /openapi.json and in the Swagger UI at /docs. You can also pass version, description, and docs_url here, but the project uses defaults. 
allowed_origins = [
    origin.strip()
    for origin in config.ALLOWED_ORIGINS.split(",")
    if origin.strip()
]
if not allowed_origins:
    allowed_origins = ["http://localhost:3000", "http://localhost:5173"]
List comprehension with filter: ALLOWED_ORIGINS is a comma-separated string like "http://localhost:3000,http://localhost:5173". Splitting on "," gives a list; .strip() removes accidental spaces around each origin; the if origin.strip() condition discards empty strings (from trailing commas or empty env var).

The fallback block ensures local development works even if ALLOWED_ORIGINS is not set in .env. 
app.add_middleware(
    CORSMiddleware,
    allow_origins=allowed_origins,
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
Middleware registration: middleware wraps every request/response cycle. CORSMiddleware intercepts preflight OPTIONS requests and adds Access-Control-Allow-Origin headers to all responses. The order matters — middleware registered first executes outermost (first on request, last on response). 
app.include_router(complaints.router)
app.include_router(voice.router)
app.include_router(call_logs.router)
# ... 15 more routers ...
app.include_router(leasing.router)
Router registration order matters for path conflicts. If two routers have overlapping paths (e.g., GET /tenants/{uuid} and GET /tenants/by-flat/{flat_no}), FastAPI matches the first route that fits. The fixed-path route /tenants/by-flat/{flat_no} must be registered before /tenants/{uuid} — but since these are in the same router file, the order within that file controls this, not the order in main.py. 
@app.get("/")
async def root():
    return {"status": "Backend running"}

if __name__ == "__main__":
    import uvicorn
    uvicorn.run(app, host="0.0.0.0", port=8000)
Health check route: GET / returns a simple JSON response. Render (the production host) and uptime monitors ping this URL to confirm the server is alive.

if __name__ == "__main__" — this block runs only when the file is executed directly (python main.py), not when Uvicorn imports it. In production, Uvicorn is always started as a separate command (uvicorn app.main:app), so this block never executes. It exists only as a convenience for local debugging.

Section 4 — Why This Design

Decision: One router per feature file vs. nested routers

ApproachProsCons
One file per feature (chosen)Each file is focused; easy to find a route; import errors are localized18 import lines in main.py; some features span multiple files
Nested routers (APIRouter inside APIRouter)Grouping by domain (e.g., all voice routes under one parent)More indirection; harder to trace which file handles a URL
All routes in main.pyZero indirectionThousands of lines in one file; merge conflicts; impossible to navigate

Decision: Plain class for Settings vs. Pydantic BaseSettings

ApproachProsCons
Plain class (chosen)No extra dependency; simple; explicitNo automatic type coercion; no validation; no field aliasing
Pydantic BaseSettingsAuto-validates types; auto-reads from environment + .env; field aliasesAdds pydantic-settings dependency; slightly more complexity

You'd switch to BaseSettings if you needed automatic type validation (e.g., fail at startup if PORT is not an integer) or multiple environment sources (env vars take priority over .env file, etc.).

Section 5 — How It Connects

Frontend (React, port 5173) │ │ HTTP request (with Authorization: Bearer <JWT>) ▼ CORSMiddleware ── checks Origin header against allowed_origins │ ▼ FastAPI router matching ── finds the correct route handler │ ▼ Route handler (in one of 18 router files) │ imports ├──► config.settings (API keys, URLs) ├──► get_authenticated_db (Supabase client with user JWT) └──► get_current_user (JWT payload)

Data flowing IN: HTTP requests from the React frontend (or VAPI/Stripe webhooks). Each request carries headers (Authorization, Content-Type) and optionally a JSON body.

Data flowing OUT: JSON responses. The settings singleton is referenced by all route files, the DB session module, and the auth dependency — it's a shared read-only dependency that flows outward from config.py.

Section 7 — Checkpoint ✓

Verify all routes loaded

Run this in your terminal while the server is running:

curl http://localhost:8000/openapi.json | python -c "import sys,json; d=json.load(sys.stdin); print(f'Routes: {len(d[\"paths\"])}')"

Expected output: Routes: 80 (or more). If you see a number around 80, all 18 routers loaded successfully. Under 70 means a router failed to import silently.

Section 8 — Exercises

Easy Add application version to the health check

Modify GET / to return {"status": "Backend running", "version": "1.0.0"}. Store the version in config.py as APP_VERSION: str = "1.0.0".

Hints

Import config inside main.py (it's already aliased there as config). Return a dict with both fields from the route function.

Solution

In config.py, add: APP_VERSION: str = "1.0.0"

In main.py, change the root route to:

@app.get("/")
async def root():
    return {"status": "Backend running", "version": config.APP_VERSION}

Success condition: curl http://localhost:8000/ returns {"status":"Backend running","version":"1.0.0"}.

Medium Add a new feature router from scratch

Create app/routes/analytics.py with a single route GET /analytics/summary that returns {"complaints": 0, "appointments": 0}. Register it in main.py.

Hints

Copy the structure from any existing router file. The router needs prefix="/analytics" and tags=["Analytics"]. The route path is "/summary" (which combines with the prefix to form /analytics/summary).

Solution

app/routes/analytics.py:

from fastapi import APIRouter

router = APIRouter(prefix="/analytics", tags=["Analytics"])

@router.get("/summary")
async def summary():
    return {"complaints": 0, "appointments": 0}

In main.py, add the import and app.include_router(analytics.router).

Success: GET /analytics/summary returns the JSON and the Swagger UI shows a new "Analytics" section.

Hard Add request logging middleware

Add custom middleware that logs every incoming request (method + path + response time in ms) to the console. It should not affect the response in any way.

Hints

Use @app.middleware("http") decorator. The middleware receives request: Request and a call_next callable. Call await call_next(request) to get the response, measure time with time.time() before and after, then return the response unchanged.

Solution 
import time
from fastapi import Request

@app.middleware("http")
async def log_requests(request: Request, call_next):
    start = time.time()
    response = await call_next(request)
    ms = round((time.time() - start) * 1000)
    print(f"{request.method} {request.url.path} → {response.status_code} ({ms}ms)")
    return response

Success: Every request prints a line like GET / → 200 (2ms) in the server terminal. Response content is unchanged.

How to Use These Modules

  1. Open any module HTML file directly in your browser — no server needed (all assets are inline).
  2. Start with Session 1 (modules 00–04) if you're new to the project. Jump to any session if you know the backend.
  3. Follow along in VS Code — each module quotes the actual source files. Use Ctrl+Click on file names to navigate.
  4. Do the exercises — solutions are in collapsible sections. Try solving first, then reveal.
  5. Read the bug sections — the bugs documented in each module were real issues encountered during development. They're the most valuable part.
  6. Use the cheat sheet as a quick reference during development without opening these full HTML files.
  7. After Module 29, continue with the session lessons — one deep-dive per build session (7–18+), with full diffs and bug journals.

Hard Rules (never break these)

✗ No /api prefix on any backend route
✗ No inline fetch() in React components — always use apiService.js
✗ No SQLAlchemy models in new code — use Supabase SDK directly
✗ No HTTP errors from VAPI endpoints — always return 200
✗ No @validator — use Pydantic V2 model_validator / field_validator
✗ No llama-3.1-70b-versatile — use llama-3.3-70b-versatile
✓ Date format: YYYY-MM-DDTHH:MM:SS (T separator, IST, no offset)
✓ user routes: get_authenticated_db | webhooks/admin: get_service_db

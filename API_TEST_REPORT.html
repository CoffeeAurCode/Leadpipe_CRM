This is the single most impactful bug. It prevents creating any tenant or complaint via the API.

What is RLS (Row Level Security)?

Supabase uses a PostgreSQL feature called Row Level Security to enforce data ownership. Every row in a table can only be seen or modified by the manager who owns it. This is done via policies — SQL rules that say "user X can INSERT a row if manager_id = their auth ID". When a policy is missing or broken, PostgreSQL rejects the insert with error code 42501.

Exact error received:

HTTP 500 Internal Server Error
{
  "detail": "Error creating tenant: {
    'message': 'new row violates row-level security policy for table \"tenants\"',
    'code': '42501',
    'hint': None,
    'details': None
  }"
}

Same error on complaints table:

'message': 'new row violates row-level security policy for table "complaints"'

How to fix:

In the Supabase Dashboard → Authentication → Policies, check the tenants and complaints tables. You need an INSERT policy like:

CREATE POLICY "Managers can insert their own tenants"
  ON tenants
  FOR INSERT
  WITH CHECK (manager_id = auth.uid());

Note: SELECT and UPDATE policies appear to work (listing/reading tenants works fine). Only INSERT is broken.

P0   BUG-2 — POST /flats Uses Form Data, Not JSON DOC Fix

The flat creation route is designed for the web UI which includes image upload. This is correct behavior — but the test plan used the wrong request format.

JSON vs multipart/form-data

JSON (Content-Type: application/json): Used for most API calls. Sends structured data as text. Cannot include binary files.
multipart/form-data: Used when a form includes a file upload (like a property photo). Each field is sent as a separate "part". FastAPI uses Form(...) to declare these fields.

The route signature in the code:

@router.post("", response_model=FlatResponse)
async def create_flat(
    flat_number: str = Form(...),     # expects form field, not JSON key
    building_id: str = Form(None),
    image: UploadFile = File(None),   # optional image upload
    ...
)

Correct curl command for test plan:

curl -s -X POST "$BASE/flats" -H "$AUTH" \
  -F "flat_number=APITEST-01" \
  -F "building_id=$TEST_BLD_ID" \
  -F "bedrooms=2" \
  -F "bathrooms=1" \
  -F "city=Montreal" \
  -F "state=QC" \
  -F "country=Canada"

The verify-phone route takes two inputs simultaneously: a query parameter (injected by VAPI with the caller's phone number) and a JSON body (the flat number the caller says they live in).

📖 Glossary
API
Application Programming Interface — the set of URL endpoints the backend exposes so the frontend (and voice agents) can read and write data.
HTTP Status Codes
Numbers the server returns: 200/201 = success, 400 = bad request (your fault), 401 = not authenticated, 403 = not allowed, 404 = not found, 405 = method not allowed, 422 = validation failed, 500 = server crashed.
JWT / Bearer Token
A JSON Web Token — a signed string that proves who you are. Sent in the Authorization header as Bearer eyJ.... Has an expiry time.
RLS (Row Level Security)
A Supabase/PostgreSQL feature that restricts which rows each user can see or modify. E.g. Manager A can only read their own tenants. When an RLS policy is missing or broken, inserts return error 42501.
Pydantic / 422
Pydantic is the Python library FastAPI uses to validate incoming data. A 422 error means the request body failed schema validation before even reaching the database (e.g. a required field is missing or a value is the wrong type).
VAPI
The voice AI platform powering the phone agents. The complaint agent answers at +14382314283; the lease agent at the provisioned number. VAPI calls the backend's tool endpoints in real-time during calls.
multipart/form-data
An HTTP content type used when uploading files. Each field is sent as a separate "part". Required for the flat creation route because it also accepts an image upload.
UUID
Universally Unique Identifier — a 128-bit random ID like 992f62d5-f7d3-48c5-bbb6-865977bf311e. Used as primary keys for all database records.
Cascade
When deleting a parent record also deletes its children. E.g. deleting a Property Group also deletes its Buildings → Flats → Tenants → Complaints. Also used here to describe test failures: if F03 fails, all tests that depend on a test flat also fail.
CRUD
Create, Read, Update, Delete — the four basic operations on a database record. Most API sections test all four operations on each entity type.
Supabase
The database platform used by this project. It provides PostgreSQL storage, user authentication (JWTs), row-level security policies, and file storage.
FastAPI
The Python web framework used for the backend. It auto-validates request bodies using Pydantic, generates OpenAPI docs, and handles routing.
OpenAPI / Swagger
A standard format for documenting API routes. The backend auto-generates this at /openapi.json. Used in this test run to discover the actual registered route paths.
P0 / P1 / P2 / P3
Priority levels. P0 = must fix now (system broken), P1 = high (feature broken), P2 = medium (not implemented), P3 = low (edge case gap).
Twilio / SendGrid
Third-party services. Twilio sends SMS messages; SendGrid sends emails. Both require valid API credentials configured on the deployed server.
Stripe
The payment processor used for subscription billing. Managers pay monthly to use the platform. The checkout session endpoint creates a Stripe-hosted payment page.

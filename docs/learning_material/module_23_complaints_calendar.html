Event aggregation per day

function getEventsForDate(date) {
    const appts = appointments.filter(a => {
        try { return a.appointment_date && isSameDay(parseISO(a.appointment_date), date); }
        catch { return false; }
    }).map(a => ({ ...a, _type: 'appointment' }));

    const comps = complaints.filter(c => {
        try { return c.created_at && isSameDay(parseISO(c.created_at), date); }
        catch { return false; }
    }).map(c => ({ ...c, _type: 'complaint' }));

    return [...appts, ...comps];
}
try/catch around parseISO: if the date string is malformed or null, parseISO throws. Without the catch, one bad record crashes the entire calendar render. The filter just excludes bad records silently. Both types get a _type discriminator so the render logic can branch on 'appointment' vs 'complaint' without checking for appointment-specific fields.

Key Patterns

window.dispatchEvent for cross-component refresh

When the chatbot or VAPI voice call creates a new appointment, the CalendarView would be stale. The pattern used is:

// Sender (chatbot after mutation)
window.dispatchEvent(new Event('refresh-appointments'));

// Receiver (App.jsx)
useEffect(() => {
    const handler = () => refetchComplaints();
    window.addEventListener('refresh-appointments', handler);
    return () => window.removeEventListener('refresh-appointments', handler);
}, []);

This decouples the chatbot from knowing about the calendar. No prop drilling, no shared state manager needed.

Why no external calendar library?

The custom grid is only ~50 lines. date-fns provides the math (eachDayOfInterval, startOfMonth, getDay). A library like react-calendar adds 50KB+ of JS for the same result. The key insight: a month calendar is just a 7-column CSS grid — the only hard part is the startOffset for the first row.

Bugs Encountered

Bug 1 — Calendar crashes on malformed date
Symptom: entire calendar blank after voice call created a complaint with a bad timestamp.
Cause: parseISO throws on invalid strings; the filter had no error handling.
Fix: wrap parseISO call in try/catch, return false to exclude bad records.
Bug 2 — Panel flickers when switching months
Symptom: slide-over panel briefly re-appeared when clicking next/prev month button.
Cause: goToPrev/goToNext didn't clear selectedDate, so the panel re-rendered with stale date data.
Fix: call setSelectedDate(null) inside goToPrev and goToNext.
Design decision — appointment date format
The backend stores appointment_date as YYYY-MM-DDTHH:MM:SS (T separator, IST, no timezone offset). date-fns parseISO handles this format but treats it as local time (not UTC). This works correctly when the frontend and backend are in the same timezone (both IST), but would break for international users. The trade-off was accepted for an IST-first product.

Answer

The panelEvents memo recalculates automatically because appointments or complaints is in the dep array. The panel re-renders showing the updated events for the selected date. This is the benefit of passing arrays as props (the parent owns the data) rather than fetching inside the calendar.

# Plan: Fix Language Detection — Agents Must Speak Only the Caller's Language

**Problem:** Both VAPI agents (complaint and lease) respond in mixed English + French throughout every call, regardless of what language the caller is speaking.

---

## Root Cause Analysis

There are **three independent sources** of bilingual output, not one. All three must be fixed together.

### Cause 1 — Static tool `request-start` messages (verbatim TTS — always bilingual)

Every tool in `build_tools()`, `build_complaint_tools()`, and `_build_lease_tools()` has a `request-start` message like this:

```python
"content": "One moment while I verify that. / Un instant, je vérifie ça."
```

These are **not generated by the LLM**. VAPI reads them verbatim via TTS the moment a tool is called. Because they are hardcoded with the `/ French` half, **every single tool invocation fires a bilingual utterance**, regardless of what language the caller spoke. There is no LLM decision happening here — VAPI just reads the string.

This means even if the system prompt language lock were perfect, the agent would still code-switch every time it calls a tool.

### Cause 2 — System prompt language policy is too weak

The current `[Language Policy]` section tells the agent to "detect and match" the caller's language, but it does **not**:
- Explicitly state that the first greeting is the **only** bilingual turn
- Explicitly forbid the `"English / French"` slash pattern in LLM-generated responses
- Explicitly forbid mixing both languages in the same response after detection

Without those hard prohibitions, the LLM inherits the bilingual pattern it sees in the first message and produces mixed responses.

### Cause 3 — `first_message` sets a bilingual template the LLM imitates

The bilingual first message is intentional and good UX (tells callers both languages are supported). The problem is that it also **demonstrates a bilingual format** the LLM may copy in subsequent turns. Without an explicit instruction that says "the first message is the only bilingual turn," the model treats bilingual output as the default style for this agent.

---

## The Fix — Three Layers

### Layer 1: Rewrite `[Language Policy]` in all three system prompts

**File:** `backend/app/services/vapi_agent_config.py`  
**Affects:** `SYSTEM_PROMPT`, `COMPLAINT_SYSTEM_PROMPT`, `_LEASE_SYSTEM_PROMPT_BASE`

Replace the current weak policy with a strict lock:

```
[Language Policy — STRICT]

The opening greeting is the only bilingual utterance in the call. Its purpose is to
announce that both languages are supported. After that point, the call is monolingual.

Once the caller speaks their first word, detect their language and lock to it for the
entire rest of the call:
  - Caller speaks English → respond in ENGLISH ONLY for all remaining turns
  - Caller speaks French  → respond in FRENCH ONLY for all remaining turns
  - Language unclear      → ask "Would you prefer English or French? /
                            Préférez-vous l'anglais ou le français?" then lock immediately

After language is detected, the following are FORBIDDEN in ALL your responses:
  - Mixing English and French in the same sentence or paragraph
  - Appending a translation of what you just said (e.g. "Thank you. / Merci.")
  - Using the "English / French" slash format
  - Switching language mid-call for any reason

Tool data rule (applies regardless of call language):
  - All text values submitted to tools must be in English
  - If the caller described something in French, silently translate before calling any tool
  - Flat numbers and ISO datetimes are language-neutral — submit exactly as spoken
```

This replaces the policy block in all three prompts. The wording is identical across agents; copy-paste it in.

---

### Layer 2: Change all tool `request-start` message content to English-only

**File:** `backend/app/services/vapi_agent_config.py`  
**Affects:** every tool in `build_tools()`, `build_complaint_tools()`, `_build_lease_tools()`

Because these strings are read verbatim by VAPI (not generated by the LLM), they cannot adapt to the caller's language. The bilingual slash format must be removed.

Change every tool message from the bilingual format to a short English-only string:

| Tool | Old content | New content |
|---|---|---|
| `Verify_phone_number` | `"One moment while I verify that. / Un instant, je vérifie ça."` | `"One moment while I verify that."` |
| `check_availability` | `"Let me check that time slot. / Laissez-moi vérifier ce créneau."` | `"Let me check that time slot."` |
| `view_active_appointments` | `"Give me a second to pull up your appointments. / Un instant, je récupère vos rendez-vous."` | `"Give me a second to pull up your appointments."` |
| `update_appointment` | `"Just a moment while I update that. / Un instant pendant que je mets ça à jour."` | `"Just a moment while I update that."` |
| `cancel_appointment` | `"One moment while I cancel that for you. / Un instant, j'annule ça pour vous."` | `"One moment while I cancel that for you."` |
| `submit_complaint` | `"Let me get that logged for you right away. / Je l'enregistre pour vous tout de suite."` | `"Let me get that logged for you right away."` |
| `find_listing` | `"Give me a second to look that up. / Un instant, je cherche ça."` | `"Give me a second to look that up."` |
| `search_available_listings` | `"Let me search our available units for you. / Laissez-moi chercher les unités disponibles."` | `"Let me search our available units for you."` |
| `submit_lease_lead` | `"Just a moment while I save your information. / Un instant pendant que j'enregistre vos informations."` | `"Just a moment while I save your information."` |

**Why English-only is acceptable:** These are 1–2 second hold filler messages while an API call is in flight. The LLM-generated response that follows immediately afterwards will be in the correct language (French or English) because of Layer 1. The brief English hold filler is a minor, acceptable trade-off compared to the major UX problem of full bilingual mixing.

> **Note:** The `build_tools()` function (legacy complaint agent) also has tool messages to update, though they currently use `"blocking": False` with no `content`. Leave those as-is — they already have no bilingual content.

---

### Layer 3: Shorten the bilingual `first_message` (optional, low priority)

The current first messages are long dual-sentence constructions:

- Complaint: `"Hi, thanks for calling — this is Alex. What's your flat number? / Bonjour, merci d'appeler — je suis Alex. Quel est votre numéro d'appartement?"`
- Lease: `"Thank you for calling! I'm here to help you find a rental unit. / Merci d'appeler! Je suis ici pour vous aider à trouver un logement."`

These are fine semantically. Optionally trim them to a shorter format that's still bilingual but less verbose:

- Complaint: `"Hello! This is Alex — I speak English and French. What's your flat number?"`
- Lease: `"Thank you for calling! I'm here to help you find a rental — I speak English and French. What are you looking for?"`

This is **optional** — the first message is intentionally bilingual and the LLM handles it correctly. Only change it if you want a cleaner delivery.

## Why the Current Setup Didn't Work

The transcriber (`language: "multi"`) and the voice (bilingual ElevenLabs) were correctly configured. The **LLM instructions** were insufficient. A voice agent's LLM will pattern-match on what it "sees" in its own prior outputs — the bilingual first message and the bilingual tool hold messages trained the LLM to treat `"English / French"` as the expected response format. The system prompt saying "detect and match" was overridden by that behavioural pattern. The fix is to (a) remove the pattern from the static messages and (b) make the system prompt instruction explicit enough that the model cannot revert to the mixed format.

Complaint 1 — “Pausing a lot, saying one moment” ✅ Confirmed

What the caller actually heard

In Transcript 1: “1 moment.” (02:30:04) as a standalone turn after find_units.

Root cause

This is the direct, predictable side-effect of the feature shipped this morning. The prompt now mandates a spoken checking phrase before every lookup and removed the old static VAPI filler. Two things make it feel like constant stalling:

  1. Lookup frequency is high. find_units runs at the location step and again after every city clarification (:1062 + the no-match “Wait → retry find_units” loop at :1074). In T2 it fired 3× (02:11:10, 02:11:30, 02:12:12) — once per garbled-then-corrected city — and each fire earns its own stall phrase. Every STT miss = one more “un moment.”
  2. The model over-applies the phrase to non-lookup turns. At T2 02:11:52 it opens “Juste un moment” then immediately recites the rent — but there is no Find Units event between 02:11:30 and that turn. It already had the data; the stall was gratuitous.
The feature itself is working to spec: phrases are French-locked, rotating, and never back-to-back repeats (1st → #1 → #3 → #4). The problem is density and misapplication, not correctness.

⚠️ The pauses are also genuinely long — T2 “Oui” 02:12:09 → reply 02:12:16 (~7s); T1 “Saint Lazole” 02:30:00 → “1 moment” 02:30:04 → answer 02:30:07. The stall phrase is papering over real tool-round-trip latency, so cutting the number of lookups helps latency and phrase count at once.

The garbled token then flows into the tool: the agent searched and spoke back “Saint-LaSort” / “Saint-Laçore” (T2 02:11:14) — i.e. it’s matching against noise, not the real city.

Root cause

Confirmed in config: language:"multi" (vapi_agent_config.py:289). This is the exact failure mode already diagnosed in lease_agent_french_city_stt_2026-06-18.md: in multi, French-accented Quebec proper nouns are mangled so badly that no downstream string-matcher can recover them (garbage in → garbage out). The planned fixes — Deepgram keyterm prompting (A1) and LLM canonicalization against the manager’s portfolio (B1) — are not yet shipped. confidenceThreshold:0.4 also silently drops the worst tokens (see secondary finding 3).

…but this time the fallback rescued the call

Unlike the earlier confounded calls (test managers had no listings → empty available_cities), Shaun’s portfolio is populated, so recovery engaged:
  • T2 02:11:14 — find_units on garbled “Saint-L’Asor” returned no match, and the agent correctly ran the no-match → offer available_cities branch (:1069-1073): “nous avons des logements à Château Gué et à Saint-Laçore” — the real cities Châteauguay and Saint-Lazare from the CSV.
  • Caller picked Saint-Lazare, the second find_units matched, and the unit was quoted correctly: 4½, Saint-Lazare, $1400/mo (CSV row 84).
The matcher + available_cities fallback is the safety net — but it costs the caller 2–3 repeats of the city, which is exactly what “not understanding him” feels like, and each repeat triggers another stall phrase.

How the two complaints compound

STT garbles the city ─► find_units no-match / wrong match ─► agent re-asks + re-runs find_units ▲ │ │ ▼ caller repeats ◄─────────── another mandated "un moment" stall phrase ─┘

Every STT miss forces an extra find_units, and every find_units earns another stall phrase. Fixing the STT (complaint 2) directly reduces the number of lookups, which directly reduces the stall-phrase density (complaint 1). They are not independent annoyances — #2 is a multiplier on #1.

Secondary findings

  1. Company name renders blank in the T1 greeting. T1: “I’m Max, the AI leasing assistant for. Are you looking…” — empty business-name variable. T2 rendered it fine (“Chantellery”). Same intermittent first-message bug flagged as open item #3 in the city-recognition session. Add a graceful fallback so it never says “…for.” blank.
  2. The agent’s own French is sometimes broken (model output, not STT).
    • T1 02:30:50: “…juillet ça fonctionne… bref c’est ce que votre propriétaire actuel sait que vous regardez pour déménager.” — the screening question came out malformed.
    • T1 02:31:04: “Tu n’es pas bien compris…” — grammatically wrong (should be “Je n’ai pas bien compris”) and switches vous → tu mid-call. [Language Policy] locks EN/FR but does not enforce vous/tu register.
  3. Back-to-back re-prompt into silence (T1). 02:29:42 and 02:29:53 are two agent turns with no caller turn between, both re-asking for the city. The caller’s prior word (“thing on low”) was low-confidence and dropped by confidenceThreshold:0.4 → it re-asked twice in 11s. Tune endpointing so a dropped token doesn’t trigger an immediate double re-prompt.
  4. CSV data hygiene (verify):
    • Agent quoted “au carré Saint-Laurent à Saint-Lazare” but CSV row 84 street_address = “2803 Rue Du Comtois”. Confirm the source so the agent doesn’t quote a building that contradicts the address.
    • state inconsistent: row 84 = “QC”, row 85 = “Quebec”. Normalize.
    • Row 83 (flat 21, $1300, 3bd/2ba) has no city, no street_address, no available_from — can’t surface sensibly in find_units. Backfill or deactivate.
